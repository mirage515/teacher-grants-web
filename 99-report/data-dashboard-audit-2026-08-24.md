# CSV 資料與儀表板一致性查核報告

**查核日期：** 2026-08-24  
**查核範圍：** `data/*.csv`、`docs/data-dictionary/`、`docs/system-manual/`、`src/lib/` 與 `src/components/dashboard/`  
**查核目的：** 在不修改任何原始資料的前提下，確認 CSV、資料載入/清理邏輯、儀表板統計與呈現口徑是否一致，並評估計算方法是否合理。

## 一、結論摘要

整體判定為：**資料來源與儀表板的主要統計口徑大致一致，程式可正常編譯與產生頁面；但目前仍有幾項需要在資料治理或介面說明上明確化的風險。**

| 項目 | 判定 | 重點 |
| --- | --- | --- |
| CSV 檔案與資料字典對應 | 通過 | 7 個 CSV 均有對應的資料字典/README 說明，程式使用的主要欄位與表頭相符。 |
| CSV 載入與欄位清理 | 大致通過 | UTF-8、去 BOM、空白清理、數字逗號清理均有處理；部分 parser 仍依欄位索引 fallback，對欄位順序變動較敏感。 |
| 獎補助統計 | 大致合理 | 原始 5,753 筆中 1 筆年度空白，會被 parser 捨棄；金額按資料列加總。 |
| 教學精進統計 | 需注意 | 3,890 列被保留、3,430 個申請群組；共同申請以年度＋申請編號去重，但存在 8 群百分比合計不為 100%。 |
| 論文統計 | 大致合理但需揭露 | 1,193 列會合併為 1,181 篇；去重鍵主要是發表年份＋正規化論文名稱，可能合併同名不同篇論文。 |
| 計畫統計 | 口徑明確但非全量 | 1,382 列中僅 677 列納入：專任、主持人、非校內補助案。這是業務篩選口徑，不應解讀為全部計畫。 |
| 教師與研究成果關聯 | 可用但有識別風險 | 研究成果以教師姓名串接，未使用跨檔案穩定識別號；同名教師可能造成誤配。 |

## 三、計算方法查核

### A. 獎補助 `/grants`

程式將年度、系所、項目、次項目、教師姓名與獎助金額讀入；金額去除逗號後轉為數字，缺少必要文字欄位或金額非數字的列會被濾除。查核得到原始總金額為 **101,318,751 元**；因 1 筆年度空白，儀表板實際總和會少掉該列金額。

主要統計採：

- 總金額：所有保留資料列的獎助金額加總。
- 教師數：不重複教師姓名數。
- 平均每位教師金額：總金額 ÷ 不重複教師數。
- 類別、系所、次項目、教師排行：依資料列金額分組加總。
- 年度趨勢：依年度及次項目/教師分組加總。

這些方法對「一列代表一筆獎補助分配」的資料模型是合理的。需注意的是，平均值是「每位出現於資料中的教師」的平均，不是每位全校教師的平均；介面文字應避免讓使用者誤解為全校教師平均。

### B. 教學精進 `/teaching`

程式將百分比、點數、金額中的非數字字元清除後轉數字；例如 `20點`→20、`100%`→100。`獎勵事項_3` 若只有未帶完整代碼的值，會依第二層代碼補成階層代碼，這有助於階層篩選一致。

摘要計算為：

- 總點數、總金額：資料列加總。
- 教師數、系所數：不重複姓名/系所數。
- 申請數：`年度＋申請編號` 去重後計數。
- 共同申請數：上述申請群組中，只要有一列申請型態為「共同」即計 1。
- 共同申請配對：同一申請群組內產生教師兩兩組合；共同申請點數以群組內所有列點數加總。

方法本身合理，尤其申請數不應直接以列數計算。不過資料檢核發現 8 個申請群組的百分比合計異常：`114/6-678`、`114/6-680`、`114/6-1251`、`114/6-2275`、`114/6-2328`、`115/10-1260`、`115/10-1261`、`115/10-1329`，合計分別包含 50%、85% 或 99% 等情況。這不會被目前 parser 排除，因此儀表板仍會使用這些列的點數與金額；若百分比是分攤完整性的控制欄位，這 8 群應列為資料品質警示。

另有一項口徑風險：共同申請的總點數/總金額以各教師列加總。若原始資料的每列已是依百分比分配後的教師份額，這是合理的；若每列重複記載整筆申請總額，則會重複計算。現有資料的典型共同申請列呈現 40%/40%/10%/10% 與對應 1,700/1,700/425/425，顯示目前較像「已分攤份額」，但建議在資料字典補充此定義。

### C. 論文 `/papers` 與 `/teachers`

程式保留具有年度、主聘系所、教師姓名、論文名稱與有效發表年份的列；目前 1,193 列均符合。顯示篇數不是原始列數，而是 `dedupePaperPublications` 後的 **1,181 篇**。

去重鍵為：

```text
發表年份 + 正規化論文名稱
```

若論文名稱空白，才退回「發表年份＋期刊名＋教師姓名」。正規化會轉小寫、統一部分破折號並移除非文字/數字字元。這對同一篇論文被多位校內作者列出時很有效，也能正確計算校內共同作者；但「同年度同名論文」可能被誤合併，尤其不同期刊或不同教師的同名論文。報告建議把「去重後論文篇數」與「原始作者列數」明確區分，並以 DOI、識別號或期刊/卷期作為更穩定的輔助鍵。

SCI/SCIE 類別正規化、共同作者、第一作者、通訊作者及國際合作等衍生統計的方向合理；類別若一篇同時有多個分類，分類分布加總可能大於去重後論文篇數，這是多值分類的正常現象，介面應標示為「分類出現篇數」而非互斥分組。

### D. 計畫 `/projects` 與 `/teachers`

計畫 parser 的業務篩選條件很明確：

1. 有識別號、年度、系所、教師姓名、計畫名稱與計畫類型。
2. `專兼任 = 專任`。
3. `工作類別 = 主持人`。
4. `專案類型 != 校內補助案`。

因此原始 1,382 列只保留 677 列。計畫件數以識別號去重，金額則以保留列的「計畫總金額(元)」加總。此計算對「一列一計畫、且每列為主持人主資料」的口徑合理；但頁面標題若使用「計畫承接總額」或「計畫總數」，必須同步說明這是外部/非校內、專任主持人子集，不是 CSV 全量。

計畫原始資料中有 496 筆經費狀態空白、部分經費來源欄位大量空白；目前 parser 不以這些欄位作篩選，因此金額統計不會因經費狀態空白而剔除資料。這符合目前程式，但應在資料品質說明中揭露。

### E. 教師 `/teachers` 與研究評鑑風險名單

教師主檔保留 415 筆，教師數、專任/兼任、編制內及平均年齡的計算方式清楚；平均年齡只排除 `age <= 0`，目前 415 筆年齡均有正值，因此實際平均沒有缺值排除影響。

研究成果風險名單的條件為：專任、講師以上、服務年資至少 3 年、年齡小於 62 歲，且缺少計畫或缺少論文/專利/技轉成果。成果資料是用 `教師姓名` 對教師主檔串接；論文另只計 `專任` 論文，計畫則沿用前述 677 筆篩選結果。這個方法可作為初步風險提示，但不是正式績效判定，因為：

- 以姓名串接可能受同名、異體字、空白差異影響。
- 資料年度/期間不同，教師主檔是 114 學年度/學期資料，論文、計畫、專利、技轉跨 112–114 年，不能直接視為同一評鑑期間。
- 「沒有成果資料」可能代表資料未匯入或口徑未涵蓋，不等於教師沒有成果。
- `Date.now()` 計算服務年資，報表結果會隨查詢日期變動；若要做正式稽核，應固定報表基準日。

## 四、已發現的資料/口徑風險分級

### 高優先

1. **教學共同申請 8 群百分比合計不為 100%。** 目前不影響列加總，但會削弱分攤完整性與資料可信度。
2. **論文去重鍵可能誤合併同名論文。** 目前 12 列被合併，其中部分可能是同一篇的多作者列，也可能包含同名不同篇；需用識別號/DOI/卷期抽樣確認。
3. **跨 CSV 用姓名串接。** 對教師研究成果與風險名單尤其重要，應優先確認是否存在同名或姓名正規化差異。

### 中優先

4. **計畫儀表板 677/1,382 的納入率約 49.0%。** 口徑合理但容易被誤讀為全量；頁面和文件應明示篩選條件。
5. **獎補助有 1 筆年度空白。** 目前被靜默排除，只在 Papa Parse 有錯誤時才 console.error；建議至少提供載入筆數/排除筆數的檢核資訊。
6. **專利 15 筆兼任資料不進入教師研究成果統計。** 這是程式明確的專任限制，但需要在頁面說明，否則使用者會以為專利資料全量納入。

### 低優先

7. **部分 parser 依欄位索引 fallback。** 欄名不存在時會按目前欄位位置取值；CSV 欄位順序變動可能造成錯欄，尤其計畫資料欄位多，建議長期改為欄名優先且缺欄即報警。
8. **CSV 編碼與檔案品質須固定。** 目前程式以 UTF-8 讀取且會去 BOM；資料交換時仍應維持 UTF-8、固定表頭及數字格式。

## 五、建議的後續驗證（本次未修改資料）

1. 由資料管理者確認教學資料的「點數/金額」是否已按百分比分攤；若是，應確認 8 群異常是否為四捨五入或漏列。
2. 抽查論文被合併的 12 列，將識別號、論文名稱、刊物、卷期、發表年份交叉比對，判定是多作者列還是同名不同篇。
3. 建立跨檔案教師對照表，優先以教師識別號或系所代碼＋姓名串接；在無穩定鍵時，至少輸出未匹配與多重匹配清單。
4. 在各儀表板顯示「原始列數、保留列數、去重後件數、篩選條件」，讓使用者能從 CSV 追溯到畫面數字。
5. 為共同申請百分比、金額、點數增加資料品質檢核規則；百分比不等於 100% 時標示警告，不要直接當成一般結果。
6. 固定研究風險名單的報表基準日與資料期間，避免同一份資料因日期不同而得到不同服務年資結果。

## 六、可重現的查核基準

本報告使用 UTF-8-sig 讀取 `data/` 下 CSV，並以資料字典欄位名稱對照 parser；沒有改寫、清洗、覆蓋或重新輸出任何原始 CSV。程式口徑以目前 source code 為準，重點參照：

- `src/lib/csv.ts`、`src/lib/stats.ts`：獎補助解析與統計。
- `src/lib/teaching.ts`：教學資料解析、申請群組、點數/金額與共同申請統計。
- `src/lib/papers.ts`：論文解析與去重。
- `src/lib/projects.ts`：計畫篩選、計畫件數與金額。
- `src/lib/teachers.ts`、`src/lib/research-assets.ts`：教師、專利、技術移轉解析與統計。
- `src/components/dashboard/*.tsx`：篩選狀態與畫面呈現。

**最終判定：** 儀表板主要數字可依目前程式重現，且計算方法在其隱含資料模型下多數合理；但在正式對外使用前，應先處理教學共同申請百分比異常、論文去重可追溯性、教師姓名串接及計畫/研究期間口徑揭露等問題。
